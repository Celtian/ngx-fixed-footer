# AGENTS.md

This file applies to the entire repository.

## Project overview

- This is an Angular workspace containing the publishable `ngx-fixed-footer` library and a demo application.
- Library source lives in `projects/ngx-fixed-footer/src`.
- Demo source lives in `projects/demo/src`.
- The library's public entry point is `projects/ngx-fixed-footer/src/public-api.ts`.
- Repository automation lives in `scripts`, `.github/actions`, and `.github/workflows`.

## Toolchain

- Use the Node.js version declared in `.nvmrc`. Run `nvm install` and `nvm use` before installing dependencies or running project commands.
- Use Bun; the exact package manager version is declared in `package.json`.
- Install dependencies with `bun ci`.
- In GitHub Actions, configure `actions/setup-node` with `node-version-file: '.nvmrc'`. Do not duplicate the Node version in workflow files.

## Development commands

- Start the demo: `bun run start`
- Lint the workspace: `bun run lint`
- Check circular dependencies: `bun run check-circular-dependencies`
- Test the library: `bun run test ngx-fixed-footer`
- Test the demo: `bun run test demo`
- Build the library: `bun run build`
- Build the demo: `bun run build:demo`
- Synchronize package versions and the library README: `bun run script:sync-projects`

Run the narrowest relevant checks while developing. Before handing off a change, run lint and the tests/builds affected by it. Workflow-only changes should at least pass formatting and YAML validation when available.

## Code conventions

- Follow the repository Prettier and ESLint configurations. TypeScript and Angular templates are strict.
- Use standalone Angular APIs, signals, `inject`, and `OnPush` change detection where they fit the existing code.
- Keep production code focused and avoid adding runtime dependencies unless the change clearly requires one.
- Keep tests beside their source files as `*.spec.ts`; tests use Vitest through Angular's unit-test builder.
- Add or update tests for behavior changes and regressions.
- Preserve the directive selector and public API compatibility unless a breaking change is explicitly requested.
- Export new public library APIs through `projects/ngx-fixed-footer/src/public-api.ts`.

## Generated and synchronized files

- Do not manually edit or commit `projects/demo/src/environments/version.ts`; it is generated by `scripts/create-version.ts`.
- Do not edit generated build output under `dist`.
- The root `README.md` is the source copied to `projects/ngx-fixed-footer/README.md` by `bun run script:sync-projects`. Update the root documentation first when public behavior changes.
- Keep the root and library package metadata synchronized through the existing scripts rather than duplicating manual changes.

## Change hygiene

- Keep changes scoped to the request and preserve unrelated work in the worktree.
- Use Conventional Commit-style subjects consistent with the history, such as `fix(scope): ...`, `feat(scope): ...`, or `chore(scope): ...`.
- Do not change package versions or generate release artifacts unless the task explicitly calls for a release.
